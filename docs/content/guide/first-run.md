先按[快速开始](/guide/quick-start/)启动 Grasp。你需要一个支持的编码工具账号，或者一个提供兼容 API 的模型服务账号。

## 保存凭据与模型组 {#model}

1. 登录后的引导中选择**编码工具授权**或**通用模型 API**。也可以从「设置 → 凭据」添加。
2. 对通用模型 API，保存服务的 Key 和 API 地址，按服务商提供的协议填写。对工具平台授权，按所选工具的提示完成登录或保存对应凭据。
3. 创建一个**模型组**。选择编码工具、刚保存的凭据或 API 账号，以及主模型。填入的是服务商给出的模型 ID，包含斜杠时保留原样。
4. 将模型组选给首次引导生成的 Agent。可以给不同角色指定不同模型组。希望先验证连接时，使用一个你能正常调用的模型即可。

## 准备仓库 {#repository}

首次引导支持登记一个 Git 仓库。公网仓库可以直接填写地址。私有仓库先保存 Token 或 SSH 密钥，在仓库记录中选中它并核对 Host、协议和提交身份。只验证对话时可以跳过仓库。详见[仓库与 Git 授权](/help/repositories/)。

完成引导后，Grasp 生成所选角色、Solo Agent 和已发布的默认工作流。接下来主动启动一条任务。

## 验证 Solo {#solo}

在首页选 **Solo**，选择已绑定该模型组的 Agent，发送一条短指令，例如「列出你当前目录中可以访问的文件，并说明你是否克隆了仓库」。

等到回复后，打开回复旁的运行信息，核对工具和模型。选择了仓库时，可在终端用 `git status` 确认工作目录与分支。继续阅读 [Solo 会话](/guide/solo/)。

## 验证工作流 {#workflow}

进入「工作流 → 默认工作流」，点击「运行」，填写需求、确认仓库和分支。用一条容易验收的低成本任务，例如补一段 README 说明并核对链接。到待办查看需要确认的澄清、审查或人工门禁，再打开运行详情确认产物与执行结果。继续阅读[运行与审查工作流](/guide/workflows/)。

如果看到模型不可用、仓库克隆失败或沙箱一直在准备，按错误阶段查[常见问题](/help/troubleshooting/)。
