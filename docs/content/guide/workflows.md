## 在画布上定义交付步骤 {#canvas}

从「工作流」打开已存在的流程，或创建一个描述你团队步骤的流程。用输入节点声明需求与运行参数，用 Agent 节点设置角色和目标，用条件分支处理测试结果，用输出节点明确交付物。

把需要确认的决定放在人工门禁上。先决定用户要看什么、允许做什么，再在节点目标中引用上游输入或产物。工作流级变量可用在适用节点上。编辑完成后先保存并检查画布，再发布要交给团队使用的版本。

## 启动运行 {#run}

点击「运行」，输入需求并核对要克隆的仓库和分支。启动时固定本次运行的仓库列表、顺序和分支。需要增加仓库时，先在[仓库设置](/help/repositories/)登记并绑定。

从运行详情查看节点状态和上下游产物。等待沙箱容量时，运行可能排队。达到节点总时限、主动取消或接管时，运行详情会显示对应的原因。

## 处理人工门禁 {#review}

在待办打开对应条目，检查 Agent 对话、预览和产物。按工作流允许的操作提交决定或继续对话，以推进或退回当前步骤。分享临时审批链接前，核对接收人和访问时限。

状态处于等待人工时，工作流会保留等待状态。E2B 沙箱在符合空闲回收条件时可先保存，收到决定后恢复环境。Docker 和 Kubernetes 环境会保留到显式停止或清理。见[沙箱生命周期](/help/sandbox-lifecycle/#active-work)。

## 验证交付结果 {#artifacts}

任务完成后查看输出节点与运行产物。确认测试结果来自这次运行，并核对最终变更和关联的仓库分支。要更改后续运行的流程，回到工作流编辑、保存并发布新版。
