# 2026-11-27（支持 PostgreSQL 存储）

- 日期：2026-11-27
- 范围：`server/`、`sandbox-gateway/gateway/`、Compose 配置、`.env.example`、`CONFIGURATION.md`、`CHANGELOG.md`
- 做了什么：Grasp 和 sandbox-gateway 各自支持通过现有数据库配置连接 PostgreSQL。启动时在事务内初始化表结构，检查两端的数据库配置是否冲突。Grasp 支持按运行标签筛选，并在初始化时使用配置的附件目录。对齐 Solo 引用搜索、审计搜索和产物筛选的匹配行为。按 PostgreSQL 的微秒精度处理澄清首条消息的送达标记，并统一模型配置及模型连接的写入和读回时间戳。
- 为什么：新部署可以将数据库交给独立的 PostgreSQL 实例管理。本地部署默认使用 SQLite。
- 如何验证：
  - 在 PostgreSQL 16.15 和 18.6 上设置 `TEST_POSTGRES_DSN` 并运行两模块的 `TestPostgres` 集成用例，覆盖建表、重启读写、运行标签、附件、沙箱状态和冲突检查。使用相同数据核对 SQLite 与 PostgreSQL 的搜索结果，包含带重音符号的产物名。模型生命周期与元数据回归通过。20 个并发请求通过两组独立连接访问同一数据库时，沙箱容量限制为 3。
  - 用全新的 PostgreSQL 18 数据库启动两个真实服务，验证登录、工作区设置、工作流发布和执行、待审批筛选。重启两个进程后继续审批，确认会话、设置、通知的已读状态和审计查询正常。在真实 Docker 沙箱里以本地模拟模型端点运行 OpenCode 和 Codex 原生 CLI，13 轮对话和 8 项 Codex Fast 检查通过，覆盖双向切换、模型和推理级别、MCP 历史读取、工作区文件保留和 Token 统计。
  - 用实际 PostgreSQL 为认证、会话、分享、HTTP 接口、工作流执行和服务层提供测试数据库。服务层的一组工具切换故障场景原来用 SQLite 专用触发器模拟，改用 GORM 回调后在两种数据库上单独复测通过。网关的 API、生命周期和存储用例通过。模拟 Token 写入失败后，重启可补记，重复回放只计一次。
  - 服务端全量回归通过。澄清首条消息用例通过五轮竞态检测。服务端覆盖率为 90.3%，网关覆盖率为 90.2%。两模块的 lint 和 vet、服务端配置文档校验、通用 CI 检查以及文档构建与审计均通过。MySQL 8.4 新库初始化的 `expose_key` 索引错误在改动前的版本中同样复现。
