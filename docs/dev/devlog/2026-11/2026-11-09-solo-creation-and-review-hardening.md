# 2026-11-09 Solo 创建恢复与评审问题修复

- 日期：2026-11-09
- 范围：`server/internal/{auth/apikey,blob,chatsession,handlers,leasewatch,models,services,router}`、`web/src/{lib/solo,lib/api,components/solo,views,locales}`、浏览器回归与依赖清单。
- 做了什么：工作流指纹改成显式客户端意图，引用解析只在收据未命中时发生；API key 按数据库身份隔离，关闭功能后可核对旧请求。Solo 创建凭据、会话和首条队列意图同事务提交，沙箱关联在 provider 请求前保存，恢复仅处理已明确受理的创建。新增按账户和会话隔离的 IndexedDB outbox，保存完成后才 POST，刷新只对账，重试使用冻结的原请求。继续已有会话时，未受理的首条文本先转交消息 outbox，防止导航吞掉草稿。
- 做了什么：租约统一为有硬截止时间的续租看门狗，默认 45 秒；瞬时错误退避重试，明确失主或到期立即取消。停止环境的意图、结果及失败记录都校验 owner、generation、expiry 和影响行数；队列空闲检查与停止意图同事务。修复异常 active 指针、队列重排后的退回位置、已派发和 legacy started 意图误重放。新增有界 SQL 展示预览，完整执行载荷仍按需读取；调度发现与迁移维护分频，停止环境退避，本机取消信号即时唤醒，跨实例每秒核对。
- 为什么：网络中断和浏览器刷新不能把同一请求变成新任务；短暂数据库故障不应提前中断仍有租约的执行；停止、重排、迁移和接管必须保留已受理意图的顺序及不重放边界。避免每次状态帧读取所有对象正文，减少多副本竞争。
- 如何验证：创建与首条消息故障回滚、16 个并发重试、账户隔离、关闭和删除后的原收据、创建与沙箱绑定间隙恢复；工作流引用改名/删除后的幂等、不同 API key、关闭功能后的确认；租约瞬时故障、持续故障、阻塞续租、晚到续租、失主及停止/关闭竞态均有专项回归。相关 Go 回归执行 `-race -count=3`。真实浏览器验证首次创建和消息 outbox 在刷新后保留原标识，刷新不自动 POST；存储事务完成才发送，已受理但响应丢失时不会再次创建。
- 剩余边界：此条不代表整体需求完成。对象正文全面改为事务外上传、事务内显式引用，以及工作区快照作业、历史迁移和后续兼容清理仍须独立完成与验证；不把已接入事件日志和仅有库的工作区归档混称为已完成。
