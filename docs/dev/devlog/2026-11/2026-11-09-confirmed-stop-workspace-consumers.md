# 2026-11-09 确认环境停机后收口工作区连接占用

- 日期：2026-11-09
- 范围：`server/internal/services/solo_environment.go`、`workspace_binding_release.go`、新增 `workspace_binding_stop.go` 和 `workspace_binding_stop_test.go`。
- 做了什么：普通 Solo 停机和关闭聊天的停机确认，在最终事务内同时关闭该环境的 IDE、终端和预览连接占用。原有显式释放流程复用同一个纯 SQL 收口函数。停机前后在父会话锁之后、物理环境锁之前核对原始工作区头；旧环境没有工作区头时也固定这一缺失状态。查询不读取对象正文、不访问运行时。
- 为什么：应用退出时可能来不及保存连接断开收据，留下持久占用，导致用户关闭 IDE 后仍不能返回工作区。只有原环境已实际停止才能证明这些连接都结束。停机失败、仍在运行、物理操作租约丢失、工作区头变化以及确认事务失败都继续保留占用，不能用超时或浏览器声明替代停止证明。
- 如何验证：服务 focused race 连续三轮通过；覆盖普通 Stop 与 Close、迟到断开幂等、其他环境占用保留、供应商失败和仍在运行、后继物理租约、工作区头及原生指纹变化、旧环境缺失头、元数据查询故障、收据写入失败时整体回滚。`go vet ./internal/services` 与 golangci-lint 通过。实际 Kubernetes 返回操作的复验等待包含本修复的新版本，未把此前受阻操作记为成功。
