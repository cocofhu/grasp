# 2026-11-09 工作流结果在状态事务中冻结引用

- 日期：2026-11-09
- 范围：`server/internal/{engine,models,services,filestore,payloadstore}/` 中工作流状态、结果 outbox 和引用清单相关文件。
- 做了什么：Run 进度事件仅记录不可变状态头，终态同事务封口指令邮箱、递增事件版本并冻结产物与指令的原始引用及元数据。投递器释放 SQL 后加载冻结来源并准备正文，以来源版本和指纹核验后提交原事件正文、消息收据及上下文版本。来源表显式区分 Text/JSON/Bytes/Binary/Image 根，原内嵌字节按字面保存。旧事件沿用原冻结 Payload，不重新读取最新 Run。
- 为什么：状态转换持锁期间的对象 GET/PUT 会阻塞暂停、恢复和完成；每次暂停复制全部产物还会放大存储。冻结 raw reference manifest 可在不复制原正文的情况下保留当时结果，也使原产物删除后的备份仍有完整引用根。
- 如何验证：定向 race 验证状态、邮箱封口、事件和来源全部原子回滚，慢存储不占 Run/邮箱锁，源记录删除后仍恢复同一结果，投递失败可复用收据。真实空本地目录恢复覆盖五种引用编码，缺失当前来源表/列不得被旧库兼容白名单隐藏。状态边界 checkpoint 在事务外准备并按 attempt/control CAS，旧 driver 的错误路径不重排新代次。隔离源码完整后端检查、核心覆盖率 90.1% 与根门槛通过。历史其它 Run serializer 接点尚未全局迁移，不据此宣称所有 ORM I/O 已消除。
