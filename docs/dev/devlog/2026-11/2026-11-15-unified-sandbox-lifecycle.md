# 2026-11-15 统一沙箱空闲回收、恢复与容量

- 日期：2026-11-15
- 范围：`server/` 生命周期、runtime、配置和 API；`web/` 设置及沙箱交互；`sandbox-gateway/gateway/` 后端驱动和恢复合同；`sandbox-gateway/sandbox/` 活动探测；配置与帮助文档。
- 做了什么：所有用途共用 60 分钟空闲时限和 15 个运行容量默认值，创建/恢复在数据库事务中统一预留容量。删除分类 TTL/容量、最长保留、租期延长、周期文件备份和恢复版本选择及其废弃测试/文案。旧设置和存量备份仅做一次性迁移，不保留运行时别名。
- 保存与恢复：Docker/K8s 验证工作区归档后删除独占运行资源，K8s 同时等待 Pod/PVC 清理；再次使用时重新生成当前工具、凭据和 MCP 配置，恢复最新成功归档后才交给任务。E2B 不做重复文件备份，等待 provider 同时证明完整快照持久化和原 guest 已退出。`solo_backup.keep` 默认 1，统一保留成功逻辑恢复点，新保存失败不淘汰上一份成功备份。
- 并发与重试：真实任务、排队和 guest 工作阻止空闲回收；等待人工的工作流可保存/释放，回复后恢复。保存阶段和释放阶段分开落盘，避免超时后卡在停止中或拿旧归档授权删除活工作区。取消先持久化清理意图，后台有界重试；明确运行资源已释放才退容量，快照物理回收仍独立跟踪。Gateway 异步创建/恢复/重装使用 attempt 标记，启动核对不会抢先改写刚创建的记录。
- 为什么：避免不同用途与后端各自维护互相矛盾的策略；同时防止只改设置 UI，却遗留环境恢复失败、沙箱消失后快照失去清理索引、或异步删除过早释放配额的问题。
- 如何验证：server 全量测试、lint/vet、配置文档检查通过，核心覆盖率 90.6%，恢复/取消/容量并发与失败回归重复 20 次通过。前端 6371 项单测、368 项 critical Playwright 用例通过，行覆盖率 91.89%，lint/类型/构建通过。Gateway lint/vet、完整覆盖率 91.0% 通过，生命周期与交接竞态 race 重复通过。guest 覆盖率 96.6%，shell/runtime smoke 通过。Agent 全矩阵 84 个切换、模型与推理等级场景通过，覆盖 8 个工具；5 个使用真实 CLI，Cursor/Trae/Kimi Code 明确使用平台协议夹具，不宣称验证了原生厂商推理。始终运行的 gate、品牌文本断言、文档构建和审计通过。
- 边界：没有升级生产 provider 或修改业务沙箱。本地 provider 协议故障注入与独立 Postgres/Redis 测试不等同真实 KVM guest 验收；旧 provider 缺证明协议会失败关闭。外部 SSH 在最后一次活动探测之后启动的工作仍存在探测窗口；文件归档仅保留工作区，E2B 恢复也不保留外部 TCP 连接。节点维护需要独立安排。
