# 2026-11-09 Solo 持久化输出、跨实例回放和历史分页

- 日期：2026-11-09
- 范围：`server/internal/chatsession/`、`server/internal/models/{chat_queue,solo}.go`、`server/internal/services/solo*.go`、`server/internal/handlers/solo.go`、`server/internal/router/router.go`、`web/src/lib/solo/`、`web/src/lib/api/`、`web/src/components/solo/`、`web/src/locales/`、`web/e2e/model-routing.spec.ts`、`CHANGELOG.md`。
- 做了什么：
  - 把已完成的不可变事件块和写入器接入 Solo 真实执行路径：接受原生输出后按有界批次保存对象正文及 SQL 索引，提交后才允许读取。发布前同时校验聊天执行权、沙箱操作租约和当前会话绑定；前置控制事件保存失败时禁止启动原生工作。
  - 取消每个回复最多保存 6000 条过程事件的内存数组；最终回复保存事件范围和计数。输出写入失败会取消对应的原生请求，保存已提交的前缀并标记结果待核对，同一收据重试不会重放操作。
  - WebSocket 在任意服务副本上读取已提交的日志页。初始状态快照明确说明持久化协议和回放起点，执行代次变化不重置全局游标；慢订阅断开后按游标重连，连续缺口不会静默跳过。被动订阅不创建本地执行器，也不恢复停止的沙箱。
  - 历史消息使用稳定的 `(created_at,id)` 游标，每页最多 200 条；界面先取最近 50 条，可加载更早记录。消息列表只读过程索引，执行过程通过具体消息的授权接口分段读取；部分过程和失败重试均保留完整回复。头部轮询缓存本次订阅的不可变执行元数据，避免反复下载过程正文。
  - 保留迁移版本的旧数组读取入口与旧内联过程读取器；旧记录达到原 6000 条边界时说明其可能不完整。下一小版本应同时移除无分页兼容入口和客户端数组兼容读取器；不能把旧记录重新包装成完整历史。
  - 未知结果的恢复会把事件范围关联到回复，并保留附件占位消息的内容和文件。工作流结果和执行不确定性使用独立的对话同步标记，避免错误声称模型切换；上下文版本 CAS 保留期间到达的新结果。
  - 修复 HTTP 客户端重复消费普通 503 响应正文，保留服务端消息及发送收据错误码。
  - 按服务端窗口合并历史，不重新排列时间相同的旧消息；按明确的轮次关联定位回复，避免工作流结果插入期间保留两份相同回复。
  - WebSocket 重连显式携带持久化日志协议版本。迁移期间不把旧进程内游标当作 SQL 日志偏移，即使两者数值碰巧重合，也会明确重置并重新回放当前轮次。
- 为什么：进程内回放缓存无法支持服务重启和跨实例阅读；截断过程会让工具动作不可查，整段历史下载也会拖慢长会话。保存失败必须保持执行结果的不确定性，不能把未保存的输出当作完成。
