# 2026-11-11（修复 Solo 停机提前超时及内部错误展示）

- 日期：2026-11-11
- 范围：`server/internal/sandbox/gateway*`、`server/internal/services/solo_{lifecycle,environment,stop_confirmation}*`、`web/src/lib/solo/useSoloChat*`、`web/src/components/solo/SoloSessionPane.vue`、`web/src/locales/{zh-CN,en}/pages.json`、`web/e2e/solo-close.spec.ts`、`CHANGELOG.md`
- 做了什么：将关闭会话和保盘停机的服务端等待预算统一为三分钟，停机 HTTP 调用使用独立预算，保留普通请求的超时、原网关路由、认证及取消行为。停机及恢复核对先读取真实进程状态，已停止时不再重发停止请求，仍在原生命周期及物理操作租约内确认后释放占用。停止异常的请求细节只写日志，接口及持久展示状态保留简短提示；前端也按错误码处理旧服务端响应，并持续查询未确认的关闭状态，确认完成后恢复原环境入口。
- 为什么：关闭会话的十秒预算和网关 HTTP 客户端的一分钟预算均短于 Kubernetes 最长两分钟的实际退出确认，正常停机可能提前被取消。回执丢失后原恢复流程仍先重发停止请求，即使原环境已经停止也可能无法收尾；内部网关地址和请求细节还会进入用户提示。
- 如何验证：新增回归确认修复前会复现短请求预算、十秒截止、丢失回执反复停止以及内部错误展示；修复后均通过。回归同时核对停止确认前保留计算占用，确认后沿用原环境及工作区、释放计算占用；前端核对轮询在实际停机后结束，浏览器覆盖旧服务端内部报错的过滤与自动确认。
- 本地检查：服务端完整测试、lint、vet、配置文档校验和 runtime 定向测试通过，核心覆盖率 90.2%；停机、回执恢复及原有操作租约回归通过 `-race`。前端 6477 项单元测试、lint、类型检查和生产构建通过，行覆盖率 91.69%；关闭及快照相关的 9 项浏览器回归通过。根目录四项门禁及文档构建、依赖安全检查均通过。
