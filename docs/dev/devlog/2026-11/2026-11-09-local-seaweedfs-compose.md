# 2026-11-09 本地 SeaweedFS 启动组件

- 日期：2026-11-09
- 范围：`start.sh`、`scripts/local-objectstore.sh`、`scripts/test-local-objectstore.py`、`compose.release.yaml`、`docker-compose.yml`、`.env.example`、中英文配置帮助、`CHANGELOG.md`。
- 做了什么：显式选择 S3 且地址和凭据为空时，由启动脚本提供独立 SeaweedFS 服务，预建 bucket 并等待其就绪。使用固定公开版本及摘要、仅发布本机 S3 端口，生成一次并保留仅允许单 bucket 的凭据，私有文件保持 600。容器直接以宿主文件所有者运行存储二进制，兼容私有 bind mount，不依赖镜像入口改写目录所有者。两套 Compose 透传外部对象存储配置；外部地址不可用、凭据不完整、存储身份损坏或已有数据丢失密钥都不会自动切换或重新生成身份。
- 为什么：没有 COS 的单机环境也需要与线上相同的对象存储协议，同时保持正文、附件和未来归档在重启后的可读性，不能把云端故障误判为允许启用空白本地存储。
- 如何验证：9 项配置回归覆盖并发首次启动、重启身份稳定、文件权限、单 bucket 授权、外部配置不落本地、损坏或丢失身份与符号链接拒绝，以及两套 Compose 一致性；根目录门槛及 docs 构建、审计全部通过。实际运行公开 4.53 镜像，对下载的全部镜像层及镜像配置核对 SHA256；发布 Compose 写入后停止并删除容器，再由源码 Compose 使用原数据重建，签名读写、列表、11,050,000 字节分段上传、完整字节 SHA、删除均通过，匿名读取及另一 bucket 访问均为 403。分别验证宿主 root 和非 root UID 场景，测试容器、网络和自有临时卷均已移除。初轮真实验证发现镜像默认降权不能读取 600 的挂载凭据，修正运行用户后完整重跑通过。此项能力面向源码栈与后续迁移版本，现有公开 3.2.0 镜像的能力边界已在示例和帮助中说明。
