# 2026-11-09 Solo 跨应用与运行时更新恢复对话上下文

- 日期：2026-11-09
- 范围：`server/internal/services/solo.go`、`solo_conversation_context.go`、`conversation_history.go` 及对应测试；`CHANGELOG.md`。
- 做了什么：每个新 Solo 聊天执行句柄在首轮读取原生运行时的稳定后端实例／Agent 代次与工作区身份；现有只读协议探测身份变化，不重置模型、不发送提示。仅在原轮次成功通过队列、执行权限与沙箱栅栏保存回复后记忆该身份；原生会话不变时后续轮次不重复注入。旧运行时没有稳定原生身份时，以同一连接句柄保守判断。上下文按 12 行分页，最多装入 64 条正文，最终提示上限为 32,000 UTF-8 字节；预算内不再固定丢掉第 12 条之前的简短回复。用户更正从较新记录开始按字节择取，再按时间正序输出，遗漏和摘录明确指向 `get_history`。不为重建提示读取完整事件日志；正文对象读取仍沿现有验证器，32,000 字节是提示上限而非对象网络读取上限。
- 为什么：真实环境在应用升级、运行时热更新后保留了全部 16 条消息，但持久上下文标志已经清零，新聊天句柄未重新注入；此前固定 12 条窗口又遗漏了预算内的早期助手结果。历史本身没有丢失，不能通过重放原请求或放宽先前上下文断言处理。
- 如何验证：应用句柄重建、同原生会话不重复、真实 WebSocket 重连保持稳定身份、同连接 Agent 代次改变重新探测、失败轮次与回复提交失败不记忆身份、准备失败不派发等聚焦回归已通过；超过 12 条简短历史完整装入、64 条正文范围与跨会话隔离、中文与表情字节预算、最新中文更正与早期圈选保留、当前输入不重复的回归也通过。上述测试 `-race -count=3` 通过（9.839 秒），services `go vet` 与 golangci-lint 通过（0 issues）。真实环境仍须使用新的显式轮次验证，不重放之前已完成的失败轮次。
