# 2026-11-09（工作区配置等待支持网关预先提供的资源身份）

- 日期：2026-11-09
- 范围：`sandbox-gateway/sandbox/cmd/backend/workspace.go`、`workspace_configure.go` 及对应测试。
- 做了什么：允许已认证、执行世系和限额完整的运行时在网关已提供有效资源 ID、私有控制及恢复目录均未配置时进入阻塞等待；保留原资源 ID，后续配置必须精确匹配。缺少世系但带有工作区限额的部分配置不再退回普通聊天模式。新 Pod 在原配置收据和资源身份不变、临时目录配置尚未恢复时可以重新配置；同一进程的未知收据或部分已配置目录仍禁止重复重启。
- 为什么：真实 K8s 首次启动时网关已经注入资源 ID，旧等待条件要求该 ID 为空，导致运行时在平台配置前退出。同样的身份不能作为停机后新 Pod 已加载临时配置的证明，否则保留的工作区和 Return 日志无法重新接入。
- 如何验证：新增测试在旧源码上复现首次启动、缺少世系和新 Pod 重新配置失败；修复后通过 Go 1.26.10 完整运行时测试、工作区测试 race 三轮、golangci-lint、vet 及沙箱核心覆盖率 96.6%。注入、Git 授权、运行时 bootstrap、预览 upstream 和免费模型契约 smoke 均通过。错误资源 ID 在写目录或改环境前被拒绝，旧配置收据与保留文件不被未知重试改写。修复后的真实 K8s 验收须使用新固定部署版本另行记录。
