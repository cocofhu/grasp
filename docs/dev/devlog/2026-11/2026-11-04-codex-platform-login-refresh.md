# 2026-11-04（Codex 登录态由平台统一换新）

- 日期：2026-11-04
- 范围：`server/internal/codexoauth`（新）、`server/internal/services/{codex_login_manager,codex_login_store,codex_device_flow,sandbox_codex_login}.go`（新）及 `workspace_credentials`、`sandbox*`、`maintenance`；`server/internal/runtime/{codex_login_hub,codex_auth,provider,model_binding,acp_*}.go`；`server/internal/sandbox/manager.go`（`WriteFileAtomic`）；`server/internal/handlers/codex_device.go`、`router.go`、`config`（`codex_login.*`）、`cmd/server/main.go`；`sandbox-gateway/sandbox/internal/provider/codex`；`web/src/components/workspace/{CodexDeviceLoginCard,WorkspaceCredentialsPanel}.vue`、`web/src/lib/workspace/useCodexDeviceLogin.ts`、API 客户端与类型、中英文语言包、`e2e/workspace-credentials.spec.ts`；用户指南 Codex 段落。
- 做了什么：refresh_token 只留在平台。`CodexLoginManager` 每 10 分钟检查，access token 剩余不足 96 小时（或无 exp 且 last_refresh 超过 6 天）时按凭据单飞换新；换新结果先按 `value_enc` CAS 保存（冲突说明用户刚重新登录，以库中内容为准；数据库失败暂存内存并重试），保存成功后才通过 `CodexLoginHub` 把去掉 refresh_token 的副本原子写入（0600）所有登记的沙箱，回合前再按版本对齐。终态错误标记 `needs_relogin` 并停止自动换新，临时错误指数退避。回合因登录被拒失败时用回合前快照判断：期间已收到新副本就直接重试，否则 `ForceRefresh(旧 access token)`，多个沙箱同时 401 只换新一次，每个回合最多重试一次，仍失败走原快速失败并保留 `CodexLoginRepasteMark`。删除旧的沙箱写回与维护前读回。新增 ChatGPT 设备码登录（会话绑定发起人，可轮询与取消），粘贴的 auth.json 必须含 refresh_token；凭据列表返回 `codexLogin{email,lastRefresh,status}`，不含任何令牌。新增配置 `codex_login.refresh_lead`／`check_interval`／`auth_base_url`，请求走 `HTTPS_PROXY`。
- 为什么：OpenAI 的 refresh_token 会轮换，多个沙箱各自换新会互相作废，导致登录被拒和反复要求重新粘贴；平台作为唯一持有者可以单次换新并统一下发。
- 如何验证：codexoauth 用 httptest 覆盖换新、终态／临时错误和设备码各阶段；manager 场景测试 5 个假沙箱，覆盖到期只换新一次、并发 401 只换新一次、CAS 冲突用户优先、保存失败重试、终态不循环，全部 `-race`；runtime 覆盖 hub 广播、回合前对齐、换新后重试一次与终态快速失败；handlers 覆盖设备码接口与归属。Web 新增 hook、卡片、凭据页单测和 3 个凭据页 e2e。server vet／全量测试／configdoc／核心覆盖率、Web lint／vue-tsc／全量单测（行覆盖率 91.9%）／构建通过。未验证：没有真实 ChatGPT 账号，设备码登录和空 refresh_token 遇到 401 的真实报错文案留作后续，届时补进 `IsCodexAuthRejectionText`。本机未安装 golangci-lint。
