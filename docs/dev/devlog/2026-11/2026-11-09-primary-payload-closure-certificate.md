# 2026-11-09（显式验证当前远端正文存储闭包）

- 日期：2026-11-09
- 范围：`server/internal/payloadstore/closure*.go`、`server/cmd/storage-admin/closure*.go`、`server/cmd/storage-admin/main.go`
- 做了什么：新增 `certify-primary --offline --workdir`，直接从配置的远端主存储回读并校验 SQL 引用和对象 SHA，禁止使用保留的本地正文兜底。SQL 维护身份、当前物理位置和原验证结果一致时才保存不可变闭包收据；成功先保留维护。使用原目录 `--resume --finalize` 重新回读后，原子记录完成时间并解除原操作维护。丢失回复可读取原收据，不清理其他操作的维护，不初始化或改变执行控制。物理与数据库配置身份均排除凭据。
- 为什么：远端位置登记不代表全部历史对象已归档；若清理兼容读取，仅依据位置或本地可读会掩盖远端缺失。提供纯 SQL 的启动校验入口，接受当前物理位置对应的闭包收据或真实复制目标证明。新空安装仅可在真实空来源封印、无既有主位置、所有业务表为空且工作区仍为固定种子时，在同一事务建立首个位置和实际种子引用摘要；已有数据不能借封印免除认证。
- 如何验证：覆盖原操作续办、显式收尾和丢失回复，撤销维护身份、改变位置/来源、缺失或损坏远端对象、保留本地可读但远端不可读、事务内对象 I/O 拒绝、只读 SQL 启动校验、当前新增数据不误伤历史收据、真实空安装与历史/隔离记录拒绝。使用独立随机前缀的真实 SeaweedFS S3 校验缺失、损坏、修复和保留原文件；另以独立空 MySQL 8.4 数据库验证跨连接收据时间精度与只读检查。相关包 race、vet 和 lint 结果由交付证据记录；未修改稳定部署、原对象或独立执行控制。
