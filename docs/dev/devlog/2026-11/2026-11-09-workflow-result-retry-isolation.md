# 2026-11-09（工作流结果投递按事件隔离失败）

- 日期：2026-11-09
- 范围：`server/internal/models/solo_workflow.go`、`server/internal/services/{solo_workflows,workflow_event_outbox,workflow_event_retry}*.go`
- 做了什么：损坏或暂不可读的结果单独保存尝试次数、固定失败阶段及下次重试时间，按到期时间筛选后再取批次，继续交付其他会话。物化之前检查会话归属，孤儿事件无需读取来源或对象；最终事务仍再次检查。并发失败使用原尝试次数和不可变身份 CAS，成功投递后不接受迟到的失败回写。兼容旧版空来源列，关闭进程时不制造失败重试；日志不保存原对象异常或其他用户正文。
- 为什么：队首任意一条来源损坏曾导致所有用户的工作流结果停止回到 Solo，且已删除会话的来源缺失可能形成永久阻塞。
- 如何验证：固定源码完整 server 测试、vet、lint、配置检查及 runtime 回归通过，server-core 覆盖率 90.1%；工作流投递、不可变来源和历史回归 race 重复三次通过。覆盖坏队首与后续正常用户、孤儿缺对象零 GET/PUT、101 条退避记录后的正常交付、修复后原收据成功、并发失败去重及晚失败不覆盖成功。每条结果仍保留可重试状态，不自动丢弃或删除对象。
