# 2026-11-09（为工作区归档提供可验证的持久上传占用）

- 日期：2026-11-09
- 范围：`server/internal/{filestore,payloadhold,payloadstore,chatsession,models}/`
- 做了什么：在上传对象之前持久化不可变的上传计划与容量占用，分别完整回读归档和清单并验证摘要；只有绑定同一存储、命名空间、作业、外部执行世代及期限的私有证明可以在调用方最终事务内固定引用。部分成功、结果未知及过期占用继续保留，恢复只读取原定对象，不重新上传或执行作业。新增归档及 JSON 清单的独立引用根与冷恢复验证。对象发布改用短元数据锁和可取消的活动发布登记，慢上传不再阻塞其他聊天发布；关闭存储会阻止新发布并等待已登记的后端调用。
- 为什么：快照必须先拥有持久的上传归属，才能安全处理中途断网、响应丢失、并发关闭和备份恢复。计划摘要不能冒充已存在的对象，验证上传也不能代替来源权限、沙箱及作业的最终检查。
- 如何验证：隔离固定源码运行 server 完整测试、vet、lint、配置文档检查及 runtime 回归通过，server-core 覆盖率 90.1%；相关包 race 重复两次通过。验证部分引用和计划对象的目标端独立恢复、旧世代及关闭后的证明拒绝、慢上传期间其他发布可用。仓库检查、文档构建和依赖审计通过。3 GiB 测试使用有界首块的流模拟，不宣称完成真实大归档上传；本批未启用快照入口、对象删除或自动作业重放，数据库事务排空和外部执行世代接线另行完成。
