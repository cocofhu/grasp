# 2026-11-09 本地 SeaweedFS 与显式新安装初始化衔接

- 日期：2026-11-09
- 范围：`scripts/init-execution.sh`、`scripts/init-execution.test.mjs`、中英配置帮助、`CHANGELOG.md`。
- 做了什么：在独立的本地对象存储变更层中，显式初始化先验证应用写入者停止，再准备原 SeaweedFS 数据和凭据、等待组件就绪，最后运行初始化管理工具。正文存储与执行控制继续各用自己的配置；普通启动不初始化。
- 为什么：新安装的正文配置可选择本地 S3，而初始化管理工具使用的正文组件必须已就绪；不能等第一次启动应用才建立组件，也不能在写入者未停止时开始准备新存储身份。
- 如何验证：真实管理工具的 SQLite 初始化及原票据测试，加上明确的 Docker CLI 协议夹具核对 source/release 两路径的停写检查、组件就绪和初始化顺序、重复调用沿用凭据、运行中拒绝且不创建存储目录；本地组件原身份、权限和重启测试另行执行，不将协议夹具记为完整镜像验收。
