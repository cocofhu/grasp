# 文件存储、交付与升级

Agent 的 `send_file(path, name?, caption?)` 会从当前授权沙箱导入文件，并向当前活动对话登记附件。`upload_file_artifact` 只导入；`send_artifact` 发送当前运行中有权读取的已有产物，可指定版本。工作流和 Solo 使用原有 artifact-store MCP，无须新增 Agent 后端。未接入 artifact-store 的 PM 工具不因此获得文件发送能力。

附件固定引用产物 ID 与 revision；覆盖同名文件产生新版本，不改变已发送文件。重复发送同一版本不会生成重复卡片。文件先复制到服务端持久目录，沙箱关闭或重建不影响已交付文件。主动删除产物后，原附件会显示文件不可用。

WebUI 可预览图片、浏览器支持的音视频、PDF、Markdown、HTML 和文本源码；HTML 使用既有隔离预览。文本预览最多读取前 2 MiB；原文件始终可以完整下载。音视频不自动播放。未知格式提供下载；具体音视频编码和 PDF 显示能力取决于浏览器。下载/预览支持 HEAD、Range、ETag 和固定版本 URL；ZIP 打包使用磁盘临时文件，不将整个媒体集合放进内存。

导入文件只供通过既有会话认证的 WebUI 访问。原有公开分享不会自动获得任意沙箱文件的权限；公开列表和正文接口均排除这些文件。访客聊天共享节点 MCP 凭据，因此访客会话活跃时拒绝无法确定归属的发送；待加入按聊天绑定的凭据和显式文件授权后再支持公开附件。

## 存储配置

- `storage.blobs_root` / `GRASP_BLOBS_ROOT`：原有附件文件目录；产物及消息负载写入其 `payloads/sha256/` 子目录。默认 `data/blobs`。
- `storage.max_file_bytes` / `GRASP_MAX_FILE_BYTES`：单文件导入上限，默认 134217728（128 MiB），启动时生效。
- 文件引用形如 `fileref:v1/text/<sha256>`，是存储目录内的相对键。它不是公开 URL，也不是访问凭据。真实文件路径由服务端推导，客户端不能指定下载路径。

将整个 `blobs_root` 挂到持久卷。使用同一数据库的所有服务实例必须挂载同一文件目录，并使用支持原子重命名及 fsync 的文件系统；容器临时目录或各实例独立磁盘不能用于共享数据库。当前实现使用文件系统，尚未实现对象存储。

图片产物存原始图片字节；Markdown、JSON、HTML 等产物正文也存文件。历史版本、Run 输入/检查点、节点输出/变量快照、事件/MCP 记录、对话消息及图片字段、待发送队列、反馈与审计负载均通过文件序列化器落盘，SQL 对应列只保留引用。文件附件元数据可以保存在 SQL。普通配置、状态、索引和权限字段继续保存在 SQL。

业务读写仍通过原来的类型和服务；序列化器兼容旧内联值与新引用，模板、守卫、历史快照不会变成“引用最新产物”。不得绕过模型序列化器用原生 SQL 写正文；迁移工具中的原生 SQL 只用于安全替换旧值。PM 消息正文搜索改为按已授权会话分批读取文件匹配，结果语义保留，大量历史上的搜索成本会增加。

文件写入使用临时文件、校验和、fsync 和原子重命名，在 SQL 引用提交前完成。SQL 回滚可能遗留未引用文件，不会提交指向半写入文件的引用。当前版本不自动删除这些文件，也不自动回收历史版本；容量管理须将数据库备份引用一并考虑，不能仅按当前数据库扫描后删除对象。

## 历史数据迁移

1. 升级前备份数据库及整个文件目录，确认持久卷容量足够。首次转换期间 SQL 旧页、备份和新文件会同时存在。
2. 新服务启动后，新写入立即改用文件引用；旧数据在迁移完成前仍可读取。后台任务按主键逐行处理旧负载，先写文件并校验，再对旧单元格做比较替换。并发编辑优先，冲突留待下次重试。
3. 迁移不改变 ID、产物版本、原有时间戳或已有链接。旧图片解码为原始字节；读取旧接口时按需重建兼容表示。已有快照保留自身完整内容，不依赖最新产物。
4. 后台日志 `file payload migration verified` 表示本轮扫描完成。失败记录只报告表/主键/字段及原因；坏图片、坏 JSON、缺失文件不会被当作成功，也不会清空旧数据。任务重试，修复后可继续。

也可以在 `server/` 下使用与服务相同的配置和环境变量执行：

```bash
go run ./cmd/migrate-files -config /path/to/config.yaml
```

命令返回 JSON 报告：`migrated`、`verified`、`deferred`、`bytes` 和 `failures`；有失败、并发冲突或中断时退出非零。再次执行会校验已有引用并继续处理余下旧数据。只有报告无失败且 `deferred=0`，才能认定活跃记录中的旧负载已全部转换。文件丢失会明确报错，不能静默返回空正文。

SQL 单元格改成引用，不代表数据库文件立即缩小。SQLite 的空闲页、WAL 和旧备份仍可能保留原来的字节。需要物理清理时，在完整迁移、备份并停止写入后，按 SQLite 维护流程执行 checkpoint 与 VACUUM；旧备份按既有保留策略另行处理。MySQL 的物理空间与备份回收遵循数据库自身的维护流程。服务不会擅自删除旧备份。

## 备份和回滚

停写后一起备份数据库和整个 `blobs_root` 是最直接的恢复方式。在线备份应先取得数据库快照，再复制文件目录；文件不可变且不自动回收，但还需保留备份期间引用到的全部文件。原有自动 SQLite 备份仅是数据库快照，恢复它时仍必须提供对应文件目录。

这次升级改变了数据库正文列的表示。已经迁移的数据库不能直接交给旧版本服务读取。回滚须恢复升级前的数据库与文件目录，或使用理解新引用格式的服务版本；仅替换服务镜像不足以回滚。不要通过把新文件重新塞回 SQL 来规避恢复流程。
